# 运行与配置

## 三种不同操作

| 操作 | 是否需要登录 | 是否会连接平台 |
| --- | --- | --- |
| `python demo.py` | 否 | 否，仅合成数据 |
| `python -m pytest -q` | 否 | 否，测试禁止外部 I/O |
| 桌面刷新 / 后台 runner | 是 | 可能；dry-run 只禁止交易写操作，并非离线 |

不要为了查看项目而启用自动模式。评估者先运行离线演示即可。

## 示例默认值

- `dry_run=true`，自动求购、新建提交、出货执行、撤单执行和邮件发送都关闭。
- 求购策略刷新为每天 12 次，即约 2 小时一轮；配置中的 `poll_seconds` 可覆盖。
- 预算窗口为主机本地时间每日 00:00 起算，不是向前滚动 24 小时。历史字段名 `rolling_success_limit` 仍用于兼容。
- 默认限额 1000 元，并开启 `include_active_order_exposure`，将已成交与未成交风险一同核对。关闭这个选项会削弱约束，不能保证多个挂单同时成交时不超限。
- 单品默认最多 5 张，策略硬上限 7 张，最低数量约束为 3 张。预算不足时不会为了凑足 10 类强行超限。
- 价格预警的示例检查周期为 1800 秒，可在本地调整；出货、行情刷新与预警是不同设置。

策略桌面配置或本地配置可覆盖默认值。启用任何自动执行前，核对最终配置、目标品类、预算、设备和当前挂单。

## 凭据与设备

`.env.example` 只列出环境变量名称。实际 `.env`、`config.local.json`、日志和状态必须保留在本机，不要截图上传或提交 Git。使用平台允许的登录和访问方式，不绕过验证码、风控或权限校验。

模拟器运行在本地，通过 Android SDK 的 ADB 连接。此仓库不分发 APP 安装包、镜像或登录态。不要开放 ADB 端口到公网。邮件凭据使用单独的 SMTP 授权码；曾经公开过的授权码应在提供方撤销并重新生成。

## 常见故障

| 现象 | 处理 |
| --- | --- |
| 登录异常 / token 失效 | 暂停执行，自行重新登录；不要把 token 发到 Issue |
| ADB 连接重置 | 检查 SDK 路径和模拟器在线状态；不要不断重复提交同一交易 |
| 队列文件损坏 | 停止执行，保留文件；对照远端订单恢复状态，不要直接清空重跑 |
| 成本缺失 | 使用成本补全模块或人工核对，不用当前市价冒充买入成本 |
| 日报缺数据 | 检查时间窗口、库存/购买记录同步和 SMTP 状态，避免把发送失败当作无成交 |

单机预算控制不是平台侧原子限额，网络延迟及外部人工交易都会影响一致性。真正部署前需要进行账号内的小规模验收和远端订单核对。本次仓库整理没有进行实盘交易。
